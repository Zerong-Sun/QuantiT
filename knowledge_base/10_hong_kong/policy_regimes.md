# 政策体制（非新闻）

## 1. 定义

**政策体制**是一段时间内、对某个主题预期现金流或折现率有方向性影响的监管与产业政策状态。输入是**人工标注的起止日期 + 主题整数分**，不是标题或舆情模型。

$$
\text{Policy}_{k,t} = \mathrm{clip}\left( \sum_{r \in R(t)} s_{r,k},\, -2,\, 2 \right)
$$

$R(t)$ 为覆盖日期 $t$ 的体制集合，$s_{r,k} \in \mathbb{Z}$ 为体制 $r$ 对主题 $k$ 的分数。

## 2. 为何不用消息面

消息是体制的**滞后、嘈杂投影**。同一条监管新闻在不同估值水平下含义不同，NLP 情绪与长线仓位的持有期不匹配。本区域只承认已经写入日历的体制，避免把「今天热搜」写进回测。

## 3. 主题与政策映射（恒生科技池）

| 主题 | 政策敏感点（结构化，非标题） |
|------|------------------------------|
| 平台互联网 | 反垄断、数据安全、游戏版号节奏、平台经济表态 |
| 硬件消费电子 | 出口、消费补贴、供应链限制 |
| 半导体 | 出口管制实体清单、设备与 EDA 限制 |
| 新能源车 | 购置税/补贴、欧美关税、国内价格竞争政策环境 |

日历文件：`quantit/policy/data/hstech_regimes.yaml`。可重叠，重叠则加总再截断。

## 4. 直觉

- 2021 年中起的平台监管收紧：平台主题持续负分，直到后续「促进民营经济」等被标成放松段
- 半导体出口管制：半导体主题负分，不自动等于平台负分
- 新能源车海外关税：EV 主题负分，不自动等于硬件负分

研究流程是：**先改 YAML 区间，再跑月频回测**，而不是先扫新闻再拟合。

## 5. 实际应用

```python
from quantit.policy.calendar import PolicyCalendar

cal = PolicyCalendar.load_default()
cal.scores_at("2021-08-01")  # dict of theme -> clipped score
```

## 6. 局限性

- 日历是事后标注，存在前视偏差；应定期做「推迟一个月标注」的稳健性检查
- 整数分无法表达政策强度的连续变化
- 未覆盖财税细则、个股处罚令；那是事件研究，不是本模块范围
